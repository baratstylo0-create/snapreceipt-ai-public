## PR-A — Dashboard export: make it work + guard it (P0)

**A1 · Export buttons do nothing (P0, straight bug).**
Symptom: clicking **Export Excel** and **Export PDF** produces no download, no error, nothing.
Fix: wire the buttons to actually trigger the download. Acceptance: clicking each button on a view **with data** downloads the file.
Likely files: `public/js/components/reports.js`, `public/js/components/payments.js`, `public/js/components/activity.js`, `public/js/api.js`; backend `routes/reports.js`, `routes/expenses.js`, `lib/excel.js`, `lib/reports.js`. **First `grep -rn "export" public/js/components` to find the current (broken) handlers.**

**A2 · Empty-export guard (P0).**
Symptom: export fires even when there's no data.
Fix: if the current view has **zero rows/activity**, do **not** export — show a popup/toast: *"No data to export."*
Acceptance: empty view → button shows the message, no file downloads; non-empty view → downloads normally.

**A3 · Confirm-before-extract popup (P2).**
For any data extract (Export Excel, Export PDF, See Report), show a confirmation popup: *"Confirm you've reviewed this data before exporting?"* → only on confirm does the extract continue.
Acceptance: cancel → nothing happens; confirm → export proceeds. Wire it once as a shared helper so all three entry points reuse it.

**A5 · Photo/PDF reference on every receipt (P2).**
Every receipt row should carry a viewable reference: the **photo** for image receipts, the **PDF file** for pdf receipts.
Likely files: `public/js/components/grid.js` / `activity.js` (row render), `routes/expenses.js`, `server.js` `/receipt/:fileId` proxy. Confirm how the image is currently served (Telegram proxy per CLAUDE.md) before extending to PDFs.

**A6 · PDF export attaches the underlying bills (P2).**
When the user exports a **PDF**, attach/append the actual bills (receipt images/pdfs) that fall in the selected time frame, so the export is self-contained company evidence.
Likely files: `lib/reports.js` (pdf builder), `routes/reports.js`. Note: this is a sizeable feature — if the pdf builder can't embed images today, say so in the PR and propose the approach (e.g. append pages) rather than half-building.

## PR-B — Dashboard review workflow (P1)

**B4 · Bulk select → approve/delete (P1).**
Add a **Select** button top-right of the review/activity list. On click: every review row shows a small tickbox, plus a **"tick all"** checkbox under the Select button. Once boxes are shown, the Select button becomes two actions: **(Approve)** and **(Delete)**. After ticking rows and clicking either → a **confirmation window** before it commits.
Likely files: `public/js/components/activity.js`, `grid.js`; backend bulk endpoints in `routes/expenses.js` (may need a batch approve/delete route — confirm what exists).

**B7 · Recently-deleted bin + recover (P1).**
Add a **bin icon** top-right (recently-deleted symbol) → opens a **"Recently deleted"** page listing bills soft-deleted from the dashboard; user can **recover** a bill from there.
Note: expenses already soft-delete via `deleted_at` (per session history) — this is mostly a **view + restore** on existing data, not a schema change. Confirm `deleted_at` exists on `expenses`. Backend: a "list deleted" + "restore" (set `deleted_at=null`) in `routes/expenses.js`.

**B8 · Permanent delete on rejected bills (P1).**
On the **Rejected** category/filter, add a delete icon on every rejected bill → **one-click permanent delete, no confirmation** (Owner explicitly wants no confirm here).
Backend: a hard-delete path scoped to rejected + the caller's scope. Confirm hard-delete is safe/allowed vs the soft-delete model — if hard delete isn't wired, this may set a "permanently_deleted" flag instead; note the choice in the PR.

**B9 · Rejected → recategorise inline (P1).**
On a rejected bill's **Status** column, add a **(v)** chevron icon at the column edge → clicking opens a **category dropdown** on that column → selecting a category **converts the bill to that category** (and presumably moves it out of rejected).
Likely files: `public/js/components/grid.js` (already has category-select logic from the 2026-07-09 fix — reuse it), `routes/expenses.js` PATCH.

## PR-D — Telegram bot (P1)

**D10 · Reject blurry photos instead of guessing (P1, data-quality bug).**
Symptom: a receipt dated 7/4/2026 was read as 14/7/2026 because the photo was unclear.
Fix: when the photo is **not clear / no proper visual**, the bot replies *"photo not clear, please resend"* and does **not** force-extract. Don't save garbage data.
Likely files: `lib/bot.js`, `lib/ocr.js`, `routes/webhook.js` (Barat's lane — coordinate). Approach: use the OCR confidence signal (`lib/confidence.js`) — below threshold → ask for resend rather than insert.

**D11 · Always ask for staff name (P1).**
Symptom: bot saves the receipt directly without asking who it's for.
Fix: whenever the bot receives a receipt, it must **ask for the staff name** before finalising, not save directly.
Likely files: `lib/bot.js` (the capture flow already has `awaiting_date` / `awaiting_remark` states — add/confirm an `awaiting_staff` step).

**D12 · Chat/menu button on PC + web (P2).**
Symptom: the chat/menu button only appears on mobile, not on the PC app or web Telegram.
Fix: make the button/menu available on PC + web too (Telegram inline keyboard vs reply keyboard — confirm which is being used and why it's mobile-only).
Likely files: `lib/bot.js`, `lib/telegram.js`.

**D13 · Duplicate-receipt handling (P1).**
Symptom: uploading a receipt already in the system saves it again.
Fix: detect the duplicate → bot **auto-replies "rejected (duplicate)"** with a **(View)** button and an **(Edit)** button. **Edit** → lets the user edit the **staff name** on the existing bill + a **Delete** option; **Delete** → removes the bill from the system.
Likely files: `lib/bot.js`, `lib/ocr.js` (dedupe key — merchant+total+date? confirm what uniquely identifies a bill), `routes/webhook.js`.
