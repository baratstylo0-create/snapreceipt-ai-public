## PR-E — Payments bugs + receipt-image export (branch `qa/pr-e-payments-fix`)

**E1 · Staff filter shows raw UUIDs instead of names (P1, confirmed bug).**
In `public/js/components/payments.js`, the **branch** dropdown maps ids→names via `state.branchNames` (see ~line 250-259), but the **staff** dropdown is filled with raw `staff_user_id` keys (~line 265-272, `fill(staffSel, 'All staff', Object.keys(staff).sort(), null)` — note the `null` name map). Result: the staff filter lists UUIDs.
Fix: build a `state.staffNames` id→`display_name` map (fetch the branch's staff directory — reuse the same endpoint the Team page uses, `lib/branches.listStaff` / whatever `team.js` calls) and pass it to `fill` for `staffSel` exactly like branches. Fall back to the raw id only when a name is genuinely unknown (mirror the branch behaviour).
Acceptance: staff filter shows human names; selecting one still filters correctly (the underlying value stays the id).

**E2 · "All branches" statement export gives no file (P1, product gap — NOT a plain bug).**
Current behaviour is **intentional**: `statementReady` (~line 84-87) rejects `All branches`/`unassigned` because a petty-cash *statement* is a single branch×month pack. The Owner expects "All branches" to produce something.
**Owner decision baked in:** do NOT force the single-branch statement to go all-branches. Instead: when an admin has **All branches** selected, the statement export buttons show a clear inline hint ("Statements are per-branch — pick a branch, or use the Manage → Export for all branches") rather than silently doing nothing. The genuine all-branches export is the **raw data export in Manage** (PR-F). 
Acceptance: All-branches + click statement export → visible explanatory message, no dead click. Single branch → exports as today.

**E3 · Receipt images in exports (P1, needs the format split below).**
Owner: "the receipt images are very important." What that means **per format**:
- **Statement PDF** — already embeds receipt images + rasterised source PDFs (`routes/statement.js` + `lib/statementPdf.js`). Verify it still works post-PR-A; no rebuild needed unless broken.
- **Raw data CSV** — cannot embed images. Add a **`receipt_url` (or receipt reference) column** so each row links to its image/PDF. (Implement in PR-F where the data export lives.)
- **Raw data Excel (xlsx)** — add a **clickable hyperlink** per row to the receipt (embedding thumbnails is a bigger lift; hyperlink first). (Implement in PR-F.)
- **New: "Evidence pack" for a filtered data view** — if the Owner wants *images bundled with a data export*, the right artifact is a **PDF (or zip) that appends each row's receipt**, i.e. the statement builder generalised beyond petty-cash. **Flag this as an Owner decision in the PR** — it's real work; confirm before building. Do NOT half-build it.
Acceptance for PR-E specifically: just verify the statement PDF still embeds images correctly (regression check) and write a test asserting it. The CSV/Excel/evidence-pack image work lands in PR-F with the relocated export.

## PR-F — Information-architecture restructure (branch `qa/pr-f-ia`)

> CTO direction (Owner-approved this session). Goal: fewer tabs, and the data export lives where you edit data.
> This touches nav + `public/index.html` + several components — the biggest-blast-radius PR of the round. Go slice by slice,
> keep the suite green each step, and **flag anything that would remove a capability** (nothing should be *removed*, only relocated).

**F1 · Fold Reports into Overview (remove the Reports tab).**
Move the Reports view into Overview behind a **segmented toggle** at the top of Overview: **`Summary | Trends`** (Summary = today's Overview; Trends = today's Reports view). Remove the standalone **Reports** nav item. All existing Reports functionality (period picker, charts, the report Excel export) stays — just relocated under the Trends segment.
Likely files: `public/js/components/nav.js` (drop the tab), `overview.js` + `reports.js` (host reports inside overview, or mount reports.js into an overview sub-panel — prefer reusing `reports.js` wholesale under a segment, not rewriting it), `public/index.html`.
Acceptance: Reports tab gone; Overview has Summary/Trends toggle; everything Reports did still works under Trends; suite green.

**F2 · Move the raw data (ledger) CSV/Excel export into Manage.**
The primary "export my data" action belongs next to the **Data editor** (excel-lite grid) under **Manage** — edit, then export the corrected data in one place. Add an **Export CSV** and **Export Excel** control to the Manage/Data-editor surface that exports the **current (filtered) expense rows**, honouring the user's scope (admin: all branches / selected filters; clerk: own branch). Route through the PR-A export guards (empty-guard + reviewed-confirm) for consistency.
- Include a **`receipt_url` column** in the CSV (E3) and a **receipt hyperlink** in the Excel (E3).
- This export **supports All branches** for admins (this is the answer to E2's all-branches need).
Likely files: `public/js/components/manage.js` + `grid.js` (the Data-editor surface), `public/js/components/reports.js`/`payments.js` (source the existing export/download helpers — reuse `triggerDownload`, don't duplicate), backend `lib/excel.js` + `routes/expenses.js`/`routes/reports.js` (confirm which endpoint yields raw rows; a CSV endpoint may need adding).
**Owner-decision flags to raise in the PR:** (a) confirm whether a raw-rows CSV endpoint exists or must be added; (b) confirm the exact columns for the CSV (propose: date, merchant, amount, currency, category, branch, staff, status, receipt_url).
Acceptance: Manage has Export CSV + Export Excel beside the Data editor; exports the filtered rows incl. receipt links; all-branches works for admin; guards apply; suite green.
